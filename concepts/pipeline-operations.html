Concepts / Pipeline operations

Pipeline reliability

A failure must stop in the right place.

Dependencies control task order. Failure isolation prevents incomplete data from reaching users.

Visual model

Run in order. Stop on failure.

A downstream task starts only after its upstream control succeeds. A failed task records its state and blocks publication.

Dependency management

Make order explicit.

Validation must finish before loading. Modelling must finish before reporting.

Failure isolation

Protect downstream users.

A failed upstream task must not publish incomplete or inconsistent data.

Recovery

Restart from a controlled state.

Retries, task state, and idempotent loads support safe recovery.

Communication

Make the failure actionable.

Record the symptom, impact, checked components, likely cause, and required action.
